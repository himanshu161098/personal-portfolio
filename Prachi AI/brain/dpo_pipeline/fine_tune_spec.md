# Weekly DPO LoRA Fine-Tuning Specification & Training Guide

This document outlines the scheduled continuous alignment and fine-tuning pipeline for the **OmniCognitive Assistant (Prachi AI V2)** using Direct Preference Optimization (DPO).

---

## 1. Objective & Alignment Targets
- Continuously align the Assistant's reasoning and object verification outputs against human feedback.
- Minimize overconfidence on ambiguous/defect inputs (enforcing the confidence threshold $\ge 0.85$).
- Preserve helpfulness and prevent degradation of factual correctness verified by Neo4j GraphRAG.

---

## 2. Dataset Schema & Ingestion

### Data Source
- Ingestion path: `dpo_training_pairs.jsonl` (generated by `dpo_pipeline/logger.py` and `/api/feedback`).
- Format: JSON Lines where each line is a JSON object:
  ```json
  {
    "timestamp": "2026-10-14T10:00:00Z",
    "user_id": "user_01",
    "prompt": "Verify object from image: camera_snap.jpg",
    "chosen": "Verified OEM Genuine component with structural defect note along lower rim.",
    "rejected": "Looks like an ordinary item without defects.",
    "metadata": {
      "confidence": 0.81,
      "critic_verdict": "RETRY",
      "model_version": "v2.0"
    }
  }
  ```

### Data Preprocessing & Validation
1. **Deduplication**: Remove identical `(prompt, chosen)` pairs.
2. **Quality Filter**:
   - Filter out pairs where `len(chosen) < 15` or `chosen == rejected`.
   - Ensure `chosen` adheres to grounding citations or verified facts.
3. **Train / Validation Split**:
   - 90% Training set
   - 10% Evaluation set (stratified by query category)

---

## 3. Training Architecture & Hyperparameters

### Base Model
- **Base Architecture**: `Qwen2.5-7B-Instruct` / `Llama-3.1-8B-Instruct` or equivalent vision-capable foundation model.
- **Quantization**: 4-bit NormalFloat (NF4) via `bitsandbytes` (QLoRA) for single GPU (RTX 4090 / A10G) compatibility.

### LoRA Hyperparameters
| Parameter | Value | Rationale |
|---|---|---|
| `r` (LoRA Rank) | `16` | Optimal balance of capacity vs memory footprint |
| `lora_alpha` | `32` | Scaling factor ($\alpha = 2 \times r$) |
| `lora_dropout` | `0.05` | Regularization against overfitting small weekly sets |
| `target_modules` | `["q_proj", "k_proj", "v_proj", "o_proj", "gate_proj", "up_proj", "down_proj"]` | Full attention & MLP adaptation |

### DPO Hyperparameters
| Parameter | Value | Notes |
|---|---|---|
| `learning_rate` | `5e-6` | Conservative LR for stable preference optimization |
| `lr_scheduler_type` | `cosine` | Smooth decay with warmup |
| `warmup_ratio` | `0.1` | 10% warmup steps |
| `beta` ($\beta$) | `0.1` | DPO divergence penalty coefficient |
| `per_device_train_batch_size` | `2` | Micro-batch size |
| `gradient_accumulation_steps` | `8` | Effective batch size of 16 |
| `num_train_epochs` | `3` | Prevents over-fitting on small batches |
| `max_prompt_length` | `512` | Prompt token limit |
| `max_length` | `1024` | Total sequence length |

## 4. Execution Script (`train_dpo.py`)

```python
import os
import torch
from datasets import load_dataset
from transformers import AutoModelForCausalLM, AutoTokenizer, TrainingArguments
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training
from trl import DPOTrainer

MODEL_ID = "Qwen/Qwen2.5-7B-Instruct"
DATA_PATH = "dpo_training_pairs.jsonl"
OUTPUT_DIR = "./checkpoints/dpo_lora_adapter"

# 1. Load Dataset
dataset = load_dataset("json", data_files=DATA_PATH, split="train")
dataset = dataset.train_test_split(test_size=0.10)

# 2. Tokenizer & Model
tokenizer = AutoTokenizer.from_pretrained(MODEL_ID)
tokenizer.pad_token = tokenizer.eos_token

model = AutoModelForCausalLM.from_pretrained(
    MODEL_ID,
    load_in_4bit=True,
    torch_dtype=torch.bfloat16,
    device_map="auto"
)
model = prepare_model_for_kbit_training(model)

# 3. LoRA Configuration
peft_config = LoraConfig(
    r=16,
    lora_alpha=32,
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM",
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"]
)

# 4. Training Arguments
training_args = TrainingArguments(
    output_dir=OUTPUT_DIR,
    per_device_train_batch_size=2,
    gradient_accumulation_steps=8,
    learning_rate=5e-6,
    lr_scheduler_type="cosine",
    warmup_ratio=0.1,
    num_train_epochs=3,
    logging_steps=10,
    eval_strategy="steps",
    eval_steps=50,
    save_strategy="steps",
    save_steps=100,
    fp16=not torch.cuda.is_bf16_supported(),
    bf16=torch.cuda.is_bf16_supported(),
    report_to="none"
)

# 5. Initialize Trainer
dpo_trainer = DPOTrainer(
    model=model,
    args=training_args,
    beta=0.1,
    train_dataset=dataset["train"],
    eval_dataset=dataset["test"],
    tokenizer=tokenizer,
    peft_config=peft_config,
    max_length=1024,
    max_prompt_length=512
)

# 6. Train & Save
dpo_trainer.train()
dpo_trainer.save_model(OUTPUT_DIR)
print(f"LoRA weights exported to {OUTPUT_DIR}")
```

---

## 5. Deployment & Rollout Schedule
1. **Trigger**: Runs every Sunday at 02:00 UTC via scheduled CI or cron if `dpo_training_pairs.jsonl` contains $\ge 50$ new pairs.
2. **Quality Gate**:
   - `eval_loss` must decrease or remain stable compared to baseline.
   - Verification accuracy against test verification suite must be $\ge 90\%$.
3. **Artifact Promotion**:
   - Merged adapter tagged: `prachi-ai-v2-dpo-YYYYMMDD`.
   - Deployed directly to inference serving backend with automated rollback.
